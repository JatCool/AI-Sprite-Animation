# Development tools (not part of the Unity package)

These are the scripts used to develop and measure the package. Paths inside them are specific to the original machine
(`C:\AI\...`, `C:\Users\limpo\...`); edit the constants at the top before using them elsewhere.

| File | Purpose |
|---|---|
| `build_workflow.py` | Regenerates the pose-slot section of `package/Workflows/AnimateDiffSprite.json` for N slots (`python tools/build_workflow.py 24`). |
| `eval_identity.py` | Identity metrics for a folder of generated frames vs the source sprite (head/torso pixel match, silhouette IoU, temporal consistency, movement, clipping, palette fidelity) and a comparison sheet. Used for the benchmark in `package/Documentation~/benchmarks.md`. Usage: `python eval_identity.py <frames folder> <source.png> [sheet.png] [label]`. |
| `posetests/` | Console tests for the AI Pose + Rig layers (OpenPose mapper round trip, limb-label tracking and facing detection, gait-cycle extraction from synthetic and from real SDPose keypoint clips (`posetests/fixtures`, trimmed real SDPose output), AI-contribution metric, validation/repair, the constraint stage (spikes, lopsided gait, foot jumps, folded legs, root lurches, foot lock, weapon, idle sway; procedural pass-through and idempotence; the four real SDPose clips), smoothing, loop closing, resampling, kinematics, the rig pose fitter on synthetic frames). Compiles the package's pure-math files against `UnityEngine.CoreModule.dll`, so it runs in seconds without Unity. Usage: `dotnet build -c Release -o <out> tools/posetests` then `<out>/posetests.exe <src.raw> tools/riglab/example_player_joints.txt [fixtures folder]` (the optional folder receives the OpenPose/pose JSON fixtures used by the Unity-side import tests). `posetests analyze <src.raw> <joints.txt> <walk|run|attack|idle> <frames> <keypoints.json ...>` analyses SDPose keypoint files (the `keypoints_*.json` that `-aiPoseDump` writes, or any ComfyUI POSE_KEYPOINT export): facing, limb-swap repairs, quality, cycle found, AI-vs-procedural contribution, and writes a `.raw` render next to each file (view with a sheet script; `KPV=1` prints the mapped joint curves). `posetests assess <src.raw> <joints.txt> <kind> <frames> <keypoints.json ...>` runs a clip through analysis AND the whole clean-up stage and prints the quantitative validation report (procedural / AI source / final metrics, corrections); env vars: `TABLE=1` per-frame joint table, `VIDEO=1` what the whole clip contains, `SHEETDIR=<dir>` writes procedural / AI-source / final `.raw` renders, `REAPPLY=1` idempotence check, `ROWS=1`/`FEET=1` grounding and foot trajectories, `NOCONSTRAINTS=1`. `src.raw` is the format written by `riglab.py` (int32 w, h, then RGBA rows bottom-up). |
| `riglab/` | Standalone .NET console harness that compiles the rig engine (`RigDefinition`, `RigAutoBuilder`, `RigAnimator`, `SpriteRig`) against Unity's `UnityEngine.CoreModule.dll` and renders frames without opening Unity. `riglab.py` drives it and writes contact sheets plus a part-map picture. `example_player_joints.txt` holds the joint coordinates of the original 48x48 test sprite and a `remap Body LegNearUpper 17 32 19 38` line (the cloak tail follows the thigh, same as the player's rig asset); the joints file also accepts `remap <FromPart> <ToPart> x0 y0 x1 y1` to try a part-map refinement without the editor. |

The rig engine is pure math on pixel arrays on purpose, so changes to it can be iterated in seconds with `riglab` and verified in Unity afterwards.
